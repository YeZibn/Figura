# Figura 上下文压缩正确性小规模评测

本目录维护三类独立任务的输入、固定多轮对话、参考答案、评分表和运行证据，用于检查上下文压缩后是否仍能完成图表分析、图表构建和图表修改。

本评测集只评估上下文压缩及其对任务结果、Token 用量的影响，与 Figura 的 30 项 Agent 端到端成功率评测分开运行、分开归档、分开统计；两者的样本和分数不合并。

每个任务包含一段固定的三轮对话。首轮提供数据或图像，后续轮次补充要求、提出核对问题并要求交付。三个任务分别运行，不共享会话历史。

标准批次结果见 [`runs/20261102-context3cat-standalone-01/report.md`](runs/20261102-context3cat-standalone-01/report.md)，逐项评分见同目录的 `scorecard-results.md`。50k 条件下三类任务均未成功触发压缩，因此本批次没有可用于判断“压缩后正确性”或压缩节省率的样本。25k 补充压力评测的各批次和汇总结论见 [`runs/20261102-context3cat-stress-25k-overview.md`](runs/20261102-context3cat-stress-25k-overview.md)；它与 50k 标准批次、30 项 Agent 端到端成功率评测分别保存、分别统计。

## 配对运行约定

1. 每项实际运行的任务分别使用一段全新会话运行“压缩组”和“无压缩基线”。两组使用相同 Provider、模型、工具注册、提示词和输入文件；除上下文容量配置外，不主动改变其他参数。
2. 初始配置沿用此前的对照约定：压缩组上下文容量 `50,000` tokens，无压缩基线上限 `100,000,000` tokens。按约 80% 阈值计算，压缩组约在 `40,000` tokens 附近触发。该容量是 Figura 的上下文管理配置，不代表 Provider 实际支持的上下文长度。
3. 只有压缩组出现至少一次成功的摘要压缩，才算测到“压缩后的任务正确性”。三轮对话未达到触发阈值时，记录为“未触发，结果不计入压缩正确性”；不要用无关填充文本强行触发。若后续为该小规模评测单独调整容量，必须在结果中记录实际值，并与此前 `50,000/100,000,000` 的 Token 降幅数据分开报告。
4. 每轮按 `conversation.md` 原文依次提交，不额外改写、追问或补充提示。分别保存两组的 Run ID、最终产物、Provider 用量和压缩事件记录。
5. 用本目录 `answer-key.md` 与 `scorecard.md` 人工评分。标准答案只供评测人员使用，不能作为 Agent 输入，也不能在对话开始前向 Agent 展示。

配对运行器为 `run_paired.py`。可选 `start-schedule-index` 与 `end-schedule-index` 可选择固定 schedule 的连续区间，启动一段新的独立批次，不会恢复之前的 Session；省略的 schedule 项会写入批次元数据。`FIGURA_CONTEXT_PILOT_TURN_TIMEOUT_SECONDS` 可覆盖单轮上限，超时或单项失败会留下证据并继续后续独立 schedule 项。

## 正确性判定

每项任务的关键项全部通过才记为任务通过；视觉可读性等质量项另外记录。两类结果不能相互抵消。每类目前只有一个案例，因此报告各任务的逐项通过情况，不把 `2/2` 或 `3/3` 表述为有统计代表性的总体正确率。

Token 用量和任务正确性分开统计。已有成都报告实验的 `8.21%` 是该单项任务的总 Provider Token 降幅；它与本目录三类任务的实验结果分开记录，不能合并称为统一平均值。
