## 图表分析单项重跑

用户要求对图表分析组重跑后，新的 100M 基线三轮通过，Provider usage 为 **231,527 Tokens**。25k 压缩首轮出现 1 次成功压缩后 Provider 流停止产生事件；运行约 12 分钟静默后由评测端停止，最终只有 **46,323 Tokens** 的不完整记录。该数值与完整三轮基线不可比较，不能计算 Token 节省率。逐项评分和证据见重跑批次的 [`scorecard-results.md`](20261102-chart-analysis-25k-rerun-01/scorecard-results.md)。

这次基线重跑独立记录为 **1/1 通过**，不合并覆盖之前续测批次中图表分析基线的 0/1 评分；压缩组仍没有完整任务样本。

## 任务正确性复核

Codex 按固定 scorecard 进行 LLM-as-Judge 复核，完整逐项依据见续测批次的 [`scorecard-results.md`](20261102-context3cat-stress-25k-continue-02/scorecard-results.md)。

- 100M 基线：**0/3** 通过全部关键项。图表分析最终差值计算与其展示的估算值不一致；构建任务轴范围/刻度不符；修改任务缺少指定颜色和数值标签。
- 25k 条件：按三类计划任务计，**0/3** 端到端成功。图表分析超时；构建仍未满足轴范围/刻度；修改仍未满足指定颜色和标签。
- 只看完整且 usage 有效的 25k 压缩配对项，**0/2** 通过全部关键项。

## 结论

25k 压力条件确实触发了压缩，但表现因任务而异：图表构建触发 1 次压缩并增加 Token 用量 8.28%；图表修改触发 3 次压缩并减少 Token 用量 29.47%；图表分析在 30 分钟内重复压缩 37 次后仍未完成首轮，且 usage 缺失。当前证据不支持将 25k 结果概括为三类任务的统一平均节省率。

构建与修改任务的失败项还涉及 ChartSpec/渲染器无法表达轴范围、自定义颜色和柱上标签的能力限制，因此这些结果不能只归因于压缩质量。此 25k 汇总作为诊断性压力测试保留，不替换 50k 标准批次结果，也不计入 30 项 Agent 成功率评测。
