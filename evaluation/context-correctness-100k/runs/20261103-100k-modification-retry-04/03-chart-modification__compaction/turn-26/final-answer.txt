## 一、四种来源各自支持什么

### 1) 源图读取（原图 + OCR 候选）
**支持的事实**
- 图像中**显示**了什么：三个面板存在、标题文字为 Quarterly Revenue by Region / Monthly Orders / Monthly Conversion Rate，轴名为 Revenue (M USD) / Orders / Conversion (%)，图例为 North/South/Central，类别为 Q1–Q4 与 Jan–Dec。
- 图像中**标注的数字**是什么：订单面板 Jul 位置标注为 105、Jun 为 108、Aug 为 115；Q4 三柱标注为 50 / 41 / 35 等。
- 图像中的几何关系：North 柱最高、四季度柱高递增、订单折线在 Dec 达峰、转化率在 Mar/Jul/Oct 有回落。
- 证据强度可用 OCR 置信度表达（如 Jul 标签 `105` 置信度约 0.999，属高可信候选）。

**不支持的事实**
- 不支持"105 是**真实**订单量"。它只证明图**这样画**，不证明绘制依据正确。
- 不支持图外信息：单位是否为真实 M USD、地区定义、数据生成过程。
- 读数本身不是绝对可靠：OCR 可能漏检、误识、标签归属错位；空结果不等于无文字。因此"图上写着 X"应表述为"图上标注读数为 X"。

### 2) 用户台账确认
**支持的事实**
- 用户**主张**经台账核实 July 应为 109，并且明确了取舍规则：以台账为准、只改 July、不改其他月份。
- 据此 109 成为本会话中**被授权的权威值**，即"按用户决定，最终 Figure 应采用 109"。
- 支持来源层级的判定：当图像标注与台账冲突时，以台账优先。

**不支持的事实**
- 不支持"台账里确实写着 109"。本会话内没有台账原件、截图、编号或日期，该值只能标为"用户确认值"。
- 不支持其余 11 个月也因此得到独立验证——它们仍是源图读数，没有第二个来源背书。
- 不支持"109 一定正确"；它是决策依据，不是可复核证据。

### 3) 模型计算
**支持的事实**
- 给定输入的**算术结果**：季度总额 83 / 97 / 110 / 126、Q4−Q1 = +43（+51.8%）、全年合计 1293→1297、月均 107.75→108.08（+0.33）、Q3 月均 114.33→115.67（+1.33）、转化率 Jan→Dec +1.4 个百分点。
- 内部一致性检验：三地区增量 16+14+13 等于总额增量 43；行合计与列合计同为 416；合计与月均相对变化同为 +0.31%（因同除以 12）。
- 换算规则的正确区分：百分点差与相对百分比不可混用。

**不支持的事实**
- 不支持输入为真。计算只是"若 July=105 则均值为 107.75；若 July=109 则均值为 108.08"，属条件结论。
- 不产生新的事实来源：它把 109 传播到合计与均值，不额外验证 109。
- 不消除舍入不确定性：均值为循环小数，需说明精度（如 108.08 为近似，精确 1297/12）。

### 4) 图表渲染
**支持的事实**
- 在给定 Figure spec 下**成功生成了一张 PNG**（1280×1002，digest `b8194b22…`，sha256 `dfb13a91…`）。
- 图像的**外观状态**：标题显示为新总标题、两列布局、三图位置（左上柱图 / 右上订单 / 左下转化率）、右下为结构性空白、月份标签旋转但可读、订单面板下 source 与 July 更正说明两行均可见、无遮挡与裁切。
- 渲染的可重复性：同 spec 两次渲染 PNG 字节一致（sha256 相同），说明图像由 spec 确定性地产生、内容未漂移。

**不支持的事实**
- 不支持数据正确；渲染器只忠实呈现输入，输入错则图照样"成功"。
- 不支持数值抽取准确、语义映射正确（系列与颜色、标签与数据点的对应仍可能错）。
- 不支持业务含义与单位真实。
- 需要区分"装配校验通过"（结构/语义规则合规）与"数据事实已核实"，两者无关。

## 二、按本会话的具体事实做归属表

| 事实 | 主要支撑来源 | 证据强度与限制 |
|---|---|---|
| 图上有 `105` 这个 Jul 标注 | 源图读取（OCR 0.999 + 目视） | 强（就该图像内容而言） |
| Jul 的真实订单量是 109 | 用户台账确认 | 仅依赖用户主张，无台账原件 |
| 最终 Figure 中 Jul 取 109 | 用户指令 + Figure spec 记录 | 强（作为"已执行的决定"） |
| Jul 105→109 差 +4、+3.81% | 模型计算 | 强（纯算术，可复现） |
| 全年合计由 1293 变 1297、月均 +0.33 | 模型计算（条件于输入） | 强算术、弱输入 |
| Q3 月均 +1.33（+1.17%） | 模型计算 | 同上 |
| 转化率 Jan→Dec +1.4 个百分点 | 源图读数 + 模型减法 | 强 |
| 图像为两列、右下留白、note 可见 | 图表渲染（视觉观察） | 强（就该 PNG 外观） |
| Figure 结构合规、字段与初始一致 | 装配校验 + 结构比对 | 强（就 spec 而言），与数据真伪无关 |
| North Q4 = 50 是"真实收入" | —— | **无来源支持**；仅"图上标注为 50"，业务真值未知 |

## 三、几条必须守住的界线

1. **渲染成功 ≠ 数据正确**：渲染只证明"图被画出来了、看起来如此"。本次四次渲染均成功，但 July 的 105/109 之争完全在渲染能力之外。
2. **OCR/读数 ≠ 业务真值**：105 是强证据的"图像内容"，不是强证据的"订单事实"。
3. **用户确认 ≠ 可复核证据**：109 是本会话的权威取值，但属未在会话内可验证的单一来源；与 105 的关系是"来源优先级"差异，不是"识别纠错"。
4. **计算 ≠ 独立验证**：所有合计、均值、百分比都是对给定输入的条件推导，输入不变则结果确定，输入错误则精确地错。
5. **结构一致 ≠ 语义正确**：三张子图逐字段与初始版相同，只说明未被改动；不说明初始读数与源图完全一致、也不说明数据业务含义成立。

**一句话总结**：源图读取约束"图上写了什么"，用户确认决定"最终采信哪个值"，模型计算负责"由此推出的量"，渲染只负责"把它画出来"；四者中没有任何一个单独构成数据正确性的证明。
