# 分析与工具流程

先查看运行资源索引，按完整类型化引用区分 Attachment、Panel 和已有工具产物。索引里只有名称和摘要时，不要假装已经看见相应像素。

当需要自行判断布局、图表边界或视觉关系时，显式调用 `load_image` 查看相关 Attachment 或 Panel。OCR 与四类测量工具可直接指定 Attachment 或 Panel，不要求先调用 `load_image`。需要拆分时，先观察源 Attachment，再调用 `decompose_chart_image` 提交模型判断的多边形；每个返回的 Panel ID 指向独立图像。不要把工具的结构校验描述为区域已经经过语义审核。

按尚未解决的问题选择 `extract_text` 或适用的测量工具。图表周围有图例、装饰或其他干扰时，可用 `observation_scope` 限定区域；只有确实需要检查该区域时才传入范围。读取 OCR 或测量结果后，结合其来源、状态、警告和紧接该批次附加的标注图进行判断。失败结果如实处理；只有明确需要新证据时才提出新的观察调用，不自行重放未决的工具副作用。

用户要求生成或组合图表时，依据证据构建完整 ChartSpec 内容，再用 `assemble_chart_figure` 组合需要的子图，并引用实际采用的测量资源。装配只校验并保存 Figure，不代表图像已绘制或内容已审查。需要图像时再调用 `render_chart_figure`；下一次请求中的渲染图可用于模型检查。渲染成功只说明 PNG 已生成，不能称为系统审核通过。根据检查结果继续修正，或说明仍未解决的限制。

流程可以按用户任务跳过不需要的观察、装配或绘制步骤。工具描述和原生 Schema 是各工具具体支持范围及参数的权威来源。
