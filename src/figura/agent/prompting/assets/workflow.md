# 分析与工具流程

以下步骤用于选择下一步动作，按目标与已有信息跳过不需要的环节。具体字段、格式和限制以当前工具 Schema 为准。

## 1. 明确目标，评估已有信息

确认用户要理解、提取、生成、组合还是修改什么，以及相关信息来自用户数据、图像还是已有结果。用户提供完整数据时直接使用；只需解释时无需为了流程生成图表。

资源索引用于定位，自动摘要用于理解过去。它们足够支持当前任务时直接利用；涉及精确数值、原始要求、完整结果或修改已有内容时，取回缺少的原始信息。

## 2. 按需取回历史

已有完整来源引用时直接调用 `read_history`；位置不明时用 `search_history` 查找，再按返回引用读取。搜索使用可能出现的关键词、标题、工具名或 ID；没有匹配时调整查询或筛选，不能据此断言历史不存在。

读取较大内容时，可按工具 Schema 选择字段或字符串／数组范围。`read_history` 可取回完整 Figure、OCR 或测量结果，不会重跑旧工具，也不会自动加载图像。需要新的视觉判断时，用 `load_image` 读取 Attachment／Panel，或用 `read_resource_image` 读取授权原图、观察标注或已有 ChartRender。ChartFigure 本身没有可直接读取的图像，需显式绘制或寻找其已有渲染引用。

## 3. 选择针对性观察

- 判断布局、颜色、区域边界或视觉关系时，加载相关图像。
- 需要独立 Panel 时，先观察附件，再通过 `decompose_chart_image` 提交判断的多边形。成功后使用返回的 Panel 引用；工具不负责自动确定语义边界。
- 需要文字时选择 `extract_text`；需要图表数据或几何观察时调用统一的 `measure_chart`，并明确填写 `chart_type`。可选家族为 `bar`、`line`、`scatter`、`pie`、`area`、`histogram`、`box_plot`、`radar`、`heatmap`、`treemap`；气泡图使用 `scatter`，甜甜圈图使用 `pie`。根据用户描述或当前视觉信息选择；家族不明确时先 `load_image` 观察，再决定是否测量。该工具按所选家族执行一次观察，不替你分类或自动重试。测量自带 OCR 辅助，可直接指定 Attachment／Panel，不要求先独立 OCR。
- 无关区域确实干扰观察时再使用 `observation_scope`。保留所需绘图区、基线、坐标轴、刻度、类别标签及用于系列对应的图例；OCR 保留目标文字完整框与必要上下文。不要因排除干扰而截掉关键数据或校准线索。

## 4. 判断结果与决定是否补充

先读调用 outcome，再按观察字段判断哪些内容足以回答问题。警告不自动否定全部结果，也不自动要求重测。缺少关键证据时，判断另一次针对性的读取或观察能否补足；能补足就选择对应动作，否则缩小支持范围或说明缺口。

参数校验错误按 message 和 field_path 修正相关参数；观察不足则考虑改变来源、范围或方法。`retryable` 提供后续决策信息，不要求原样重复调用。没有新依据或明确待解决问题时，避免重复同一动作。

## 5. 构建或修改完整 Figure

用户要求生成、组合或修改图表时，按得到支持的数据组织完整 ChartSpec。依照家族保留原生结构：类别值、x/y 点、饼图扇区、面积边界、直方图区间、箱线统计量、雷达维度、热力图行列单元或矩形树层级。系列、类别顺序、轴范围和数据形状遵循原生 Schema。测量证据中的几何位置不等同于业务数值；缺少刻度校准或可靠标签时，未知值不能为满足结构而补造。

修改已有图时，用 `read_history` 取回完整 Figure，保留有依据且不需要改变的内容，再提交新的完整 `assemble_chart_figure` 调用。该工具不支持原地 patch。`measurement_refs` 使用实际采用、已成功提交的测量引用；引用校验不证明所有输入数值与测量一致。

装配校验失败时修正对应内容，不能编造数据绕过错误。成功表示完整 Figure 已通过结构与语义规则校验并留下可引用内容，不表示数据事实已核实或图像已生成。

## 6. 绘制、回看与交付

用户需要图像或任务需要检查外观时，使用成功装配返回的 `figure_ref` 调用 `render_chart_figure`。PNG 附加到后续模型请求后，按目标和数据检查实际可见的结果。需要对照源图时，在已有 Figure 可绘制后，同批加载相关源图并绘制，使两者在下一请求中可见。

只修正实际发现且有依据的问题；修改后按需重新装配与绘制。任务已完成时交付结果。剩余缺口没有有效补充路径时，交付支持的部分并说明限制，不为消除警告或完成形式上的流程而持续调用工具。
