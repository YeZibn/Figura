# multimodal-tool-observations Specification

## Purpose

Enable an agent to inspect visual evidence generated by its tools while keeping
image transport bounded, attributable to the originating call, and isolated
from arbitrary local files.

## Requirements

### Requirement: Tool-generated images become model-visible observations

The system SHALL convert each valid image generated by a tool into a multimodal
model input containing the image, its caption, and the identity of the
originating tool call. The structured tool result SHALL remain available beside
the visual observation.

#### Scenario: Valid generated image is observed on the next model turn

- **WHEN** a tool call returns structured data and a supported generated image
- **THEN** the next model invocation receives the structured result and an image
  content part whose caption identifies the originating tool call

#### Scenario: Multiple visual results retain their associations

- **WHEN** one model turn invokes multiple tools and more than one call produces images
- **THEN** all required structured tool results are recorded and each image is
  presented with the correct tool name, call identifier, and caption

### Requirement: Generated image handling is bounded

The system SHALL accept only configured image media types and payload sizes for
tool-generated observations. An invalid image SHALL produce a structured
warning, SHALL NOT be attached to a model request, and SHALL NOT discard the
call's valid structured data or other valid images.

#### Scenario: Unsupported image does not break the agent loop

- **WHEN** a tool result includes valid structured data and an image with an
  unsupported media type or invalid payload
- **THEN** the model still receives the structured data and a warning, the
  invalid image is omitted, and the agent loop continues

#### Scenario: Oversized image is rejected independently

- **WHEN** one generated image exceeds the configured payload limit while
  another image from the same turn is valid
- **THEN** only the oversized image is omitted and the valid image remains
  available to the model

### Requirement: Visual observations are isolated to the agent run

The system SHALL retain generated image payloads only for the owning agent run,
SHALL clear retained payloads when that run is reset or closed, and MUST NOT
allow a tool result to attach an arbitrary local file by path.

#### Scenario: Reset releases generated observations

- **WHEN** an agent has processed visual tool observations and is reset
- **THEN** generated image payloads retained by that agent are released while
  user-provided source images remain untouched

#### Scenario: Arbitrary path is not accepted as a generated image

- **WHEN** a tool attempts to describe a visual observation only by naming a
  local path that it did not provide as a generated image payload
- **THEN** the path is not attached to the model and the result contains a
  structured warning

### Requirement: Visual observation references are client-loadable

The execution boundary SHALL expose each persisted visual observation with a
stable observation reference, owning session and run correlation, supported
media metadata, and an authorized preview resource while the observation is
available. An expired, missing, or unauthorized observation SHALL remain
renderable as bounded metadata without a broken or fabricated image URL.

#### Scenario: Persisted visual observation is previewable

- **WHEN** a run event contains a valid observation ID and the observation is
  still available to the owning session and run
- **THEN** the client can request the observation resource and display the
  returned image beside its originating tool call and caption

#### Scenario: Observation expires without leaking content

- **WHEN** an observation resource has expired or has been removed
- **THEN** the client displays its bounded caption and an explicit unavailable
  state, and no image bytes or local path are substituted

#### Scenario: Observation resources remain isolated

- **WHEN** a client changes the session or supplies an observation reference
  belonging to another run
- **THEN** the Gateway rejects the resource request and the client does not
  display the returned reference in the new session or run
