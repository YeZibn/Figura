## Why

当前压缩以完整 Run 为边界，并始终保留最新的先前 Run，因此最近一个完整 Run 无法参与摘要；历史只有一个先前 Run 时也没有可压缩内容。固定摘要长度提示与目标窗口预算脱节，不能表达“保留近期原文和压缩摘要各占当前 Provider 容量的 10%”。

需要把压缩从 Run 数量策略改为基于实际请求 Token 估算的历史切片策略，在不修改规范 Run 事实的前提下，让最近完整 Run 的较早交互进入摘要、最近交互保留原文，并使预算随当前 Provider 的 env 容量配置变化。

## What Changes

- 继续以实际准备请求估算达到所选 Provider/model 配置容量的约 80% 作为自动压缩触发条件。
- 按所选 Provider 配置容量 `C` 动态计算历史原文尾部预算 `0.1 × C` 和完整滚动摘要预算 `0.1 × C`；两项是历史部分的近似预算，不宣称压缩后完整请求仅占窗口 20%。系统提示、工具、资源目录和当前活动 Run 另计。
- 从最近历史向前选择完整交互作为原文尾部，最新完整 Run 也可按交互边界部分进入摘要。一个交互中的助手工具调用批次与对应结果不得拆分；预算因交互粒度产生小幅超出时保留完整交互。
- 用来源引用生成并更新完整滚动摘要；`0.1 × C` 的摘要预算由协调器计算和持久化，作为软预算记账，不强制写入模型提示、不要求填满预算、不硬截断有效内容，也不改变或删除规范 Run 事实。
- 保留当前活动 Run 的输入和必需已提交前缀；失败或中断 Run 及其之后无法跨越的历史留在原文尾部，避免跳过异常事实形成非连续摘要；压缩失败时保持现有安全回退行为。
- 为 Run 内部覆盖边界更新检查点消费、历史投影、摘要输入和恢复绑定，并通过多窗口实验比较 Token 节省、摘要有效性、提示长度影响和历史事实恢复。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `session-context-compaction`: 更新历史保留与摘要预算、Run 内完整交互切片、动态容量目标、最近完整 Run 覆盖及压缩后的请求估算合同。

## Impact

- Agent：`src/figura/agent/context_compaction.py`、`request.py`、`executor.py` 与压缩请求构造。
- Runtime：`SessionContextCheckpoint` 和 `ContextCompactionOperation` 的 Run 内覆盖边界验证、持久化与恢复绑定；优先复用现有记录和工具序列字段，只有在无法无歧义表达完整交互边界时才提出必要的模型变更。
- Prompt：`src/figura/agent/prompting/assets/compaction.md` 移除固定长度值，配合运行时按所选 Provider 容量计算的目标；实验需检查数字提示是否诱发摘要膨胀。
- 测试与文档：覆盖动态 env 容量、最新 Run 部分压缩、工具批次完整性、异常尾部、失败回退、检查点恢复和实际请求估算；同步 Figura 上下文压缩规格与实现文档。
