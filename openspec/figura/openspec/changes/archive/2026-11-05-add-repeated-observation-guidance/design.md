## Context

动机见 proposal.md。当前 `ToolCallFact` 保存工具名、Registry 版本、原始参数和调用身份；`ToolResultFact` 分离保存 outcome、结构化 result 与 attachments。`AgentRequestBuilder` 从 Run 事实构建普通请求，压缩投影会隐藏部分旧过程，但不会删除原事实。Provider 重试已有不可变逻辑请求绑定。

`extract_text` 和 `measure_chart` 的 result 都包含来源与结构化观察，标注图由单独的 attachments 表达；当前 OCR 的 snippet ID 与测量 evidence/calibration ID 属于结果内部结构，第一版保留，不按字段名泛化删除。具体参数见 `tools/implementations/extract_text.py`、`measure_chart.py` 与 `measurement_schema.py`。

现行规格明确不施加累计 Run 配额。本方案仅加入事实反馈，与该合同兼容；不改变旧系统或共享工具运行时。

## Goals / Non-Goals

**Goals:** 从同一权威 Run 前缀确定性推导精确重复，为模型提供短而可追溯的运行提示；保持完整批次、恢复和 Provider 请求身份边界。

**Non-Goals:** 判断任务语义进展、近似结果比较、图像相似度、几何等价、强制退出、缓存替代执行、自动失败重试、跨 Run 去重，以及增加前端控制或持久测量状态。

## Decisions

### 1. Agent 拥有调用期投影，Runtime 继续拥有事实

建议新增 Agent 内部纯投影模块 `repeated_observations.py`，输入为普通请求使用的已授权 `RunState`，输出为不可变提醒集合。它读取有效配对的 ToolCallFact/ToolResultFact，沿用现有事实完整性校验，不绕过未配对或损坏事实的拒绝路径。不额外查历史 Session，不运行工具，不访问标注图文件。

拒绝新增 Runtime 重复计数器：已有调用事实足够重建，双份状态会增加事务、恢复和迁移成本。拒绝放在测量 handler：它看不到当前 Run 的完整工具决策序列，也不应决定 Agent 策略。

### 2. 两级精确键，不泛化语义去重

动作键为 `(tool_name, registry_version, canonical_arguments)`。沿用共享严格 JSON 解析和稳定编码规则，保留参数是否缺省、数组顺序与数值表示的既有编码语义。不排序多边形、不归一化范围、不做数值容差；不同来源身份保持不同动作。

观察键为完整 `result` 的规范 JSON。保留其全部字段，包括内部 snippet/evidence/calibration 标识，不删除业务 ID；不纳入 ToolResultFact 的 call/attempt 身份、created_at 等事实 envelope 或 attachments。当前 result 不需要排除动态字段；未来若增加此类字段，必须显式更新工具对应比较合同和测试，不允许按 `id`、`timestamp` 等名字自动剔除。

如用摘要索引加速，应在匹配时核对规范内容，不能把哈希碰撞当作相等。规范内容仅供内存比较，不进入 Prompt、日志或公开事件。共享载荷与深度保护继续适用，不静默截断后判相等。

### 3. 最新观察决定每个动作当前展示的提醒

按工具事实顺序扫描当前 Run 已提交成功调用，为每个动作的每种观察维护计数与最近两个匹配结果引用，并记录该动作最新成功观察。只投影最新观察对应计数不少于 2 的组，因此一个动作最多一条提醒。

例如同一动作的观察为 A、A、B 时，不再显示 A 的旧提醒；A、B、A 时，显示 A 出现两次的事实，不宣称连续两次一致。失败或未解决调用不计数、不重置成功观察；已有异常上下文仍由现行请求层提供。工具恢复的多个 attempt 最终仍对应一个逻辑调用，只计一次。

允许全 Run 内的非连续匹配，并合并同批重复；不增设人为窗口或隐藏条目配额。按最新匹配结果的 tool_sequence 升序稳定输出，一个动作的提醒随最新事实更新而非追加历史告警。一次扫描建立索引，避免逐对比较；内存随当前 Run 不同动作/观察数增长，不建立全局缓存。

### 4. 提醒字段与生命周期

内部 `RepeatedObservationNotice` 由 Agent 持有，建议字段如下；具体命名可在实现中与既有类型对齐，但语义与公开边界固定：

| 字段 | 类型/用途 | 生命周期与边界 |
| --- | --- | --- |
| `tool_name` | 封闭的 OCR/测量工具名 | 纯投影写入，Prompt 可见 |
| `matching_call_count` | >=2 的匹配成功逻辑调用数 | 从当前 Run 事实计算，Prompt 可见 |
| `recent_result_refs` | 最近两个匹配结果的既有类型化来源引用 | 使用现有 ref 编码/读取合同，不新造 ID；Prompt 可见 |
| `latest_result_sequence` | 用于确定性排序的事实序号 | 内部投影，不单独持久化或公开 |

动作键、观察键及索引仅为模块内部计算数据，不添加到 `RunExecutionState.resources` 或数据库。请求构建器在资源投影/消息压缩前保留的权威 RunState 上计算提示，并将安全字段以确定性 JSON 放入既有动态 running-state SYSTEM 块的 `repeated_observations` 段；没有提醒时省略该段。继续使用原有授权来源引用格式，提示不包含原参数、源文字、完整结果或文件路径。

`workflow.md` 增加稳定解释：此段是重复事实而非错误或停止指令；考虑改变范围/方法或带限制交付，同时保留所有工具权限。中文提醒语句固定，不插入来源可控字符串作为指令。示例：“当前 Run 中该动作已在相同来源和参数下成功执行 2 次，结构化观察一致。再次原样调用可能无法提供不同观察；请结合未解决的问题考虑调整范围或方法，没有有效补充路径时交付支持的部分并说明限制。”

### 5. 普通请求、批次、压缩与重试边界

仅在批次闭合后为下一普通模型请求准备提醒；不额外调用模型，也不在已接受批次中插入拦截。工具结果、图片附件、响应与工具配对关系均不变。

重启从持久前缀重建相同投影。压缩可以移走 Prompt 的旧原文，但计算仍覆盖当前 Run 的授权完整已提交事实，因此引用仍可用现有 `read_history` 读取。摘要请求不注入重复提醒。

普通请求资产与动态内容继续进入现有请求身份计算。Provider 重试按原冻结前缀、Prompt 资产与请求绑定重建；不得用后来状态重新计数。如现有绑定校验因代码/资产变化无法复现，应遵循现有安全拒绝策略，不静默更换请求。上线重启的运行兼容性须遵守现有绑定合同，不为本功能迁移旧请求。

## Risks / Trade-offs

- [浮点置信度或内部 ID 微小变化导致漏检] → 明确第一版只报告精确结构化一致，不声称检测所有无效循环；不以容差换取误报风险。
- [提醒被模型忽略] → 保留调用权限是明确选择；通过测试证明提醒可见，不将测试通过宣传为模型必然收敛。
- [重复提示占用上下文] → 每动作一条、只含计数与最近两个引用，不堆积全文；不暗中引入新限额或截断规则。
- [长 Run 扫描成本] → 一次索引扫描，不逐对比较、不全局缓存；性能随事实规模验证，后续缓存不能取代事实权威。
- [历史同观察再次出现被误解为连续重复] → 提醒仅称匹配次数，不称连续次数；最新观察变化后选择对应组。
- [Prompt 更新影响已有冻结请求] → 复用现有资产校验和失败路径，运行中请求不得静默换提示。

## Migration Plan

无需数据库迁移、工具 Registry 升版、前端或公共协议变更。按实现任务更新 Agent 代码、Prompt、测试与 `docs/figura/agent.md`/总览；规格经后续同步流程落入主规格。本次提案只创建规划文件。

部署与回滚遵守现有 Provider 请求绑定兼容规则：新请求使用当前资产，既有请求仅在原绑定可重建时重试。回滚代码不修改已提交工具事实或生成补造结果；不承诺跨资产版本继续在飞请求。
