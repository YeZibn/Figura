## Why

当前完整请求估算不能解释历史与目录各自造成的窗口压力，而且所有旧用户原文始终注入，使历史过程压缩后仍可能持续膨胀。需要分开统计完整输入和历史内容，允许旧用户输入及当前 Run 的已完成过程进入摘要，同时按预算筛选资源定位信息。

## What Changes

- 分别估算完整请求与历史内容，提供当前用户输入、摘要、原始历史、资源目录、规则/工具/状态和图片的内部组成信息；所有计数均为本地估算，不把历史占比标成窗口占比。
- 当前 Run 的用户输入完整保留；此前用户输入随其对应历史覆盖进入可追溯摘要，不再无条件重发全部旧用户原文。
- 此前与当前 Run 的已提交完整交互共用连续前缀摘要与近期原文后缀，保护最新待回看视觉批次、不完整批次与未解决动作。
- 维持约 80% 完整输入压力触发线，根据必要输入后的剩余空间分配摘要/近期历史软目标；只有新增可覆盖历史时才发起新摘要，不为达到阈值反复摘要同一覆盖范围。
- 在现有引用筛选基础上增加确定性的资源目录分层和软预算，精确资源引用不交由模型改写，完整授权目录及历史读取仍可用。
- 摘要、选择规则和恢复范围版本化；冻结请求不重新绑定。保持现有 Provider/载荷保护、故障回退与异常历史安全边界，不引入 Run 配额或基于近似 token 数的普通请求硬拒绝。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `session-context-compaction`: 双统计、旧用户输入覆盖、动态历史目标、目录软预算、有限压缩及恢复合同。
- `agent-react-execution`: 普通请求按摘要覆盖投影旧用户输入，保留当前输入和完整工具交互，明确完整持久事实与模型可见历史的区别。

## Impact

- 涉及 `src/figura/agent/request.py`、`context_compaction.py`、Prompt 资产、Provider 本地估算复用、Runtime 压缩操作的版本化选择计划与相关测试。
- 保持现有 `ContextEstimate` 持久格式；新增分项统计作为调用期派生值，不直接扩展严格持久 decoder。新策略需兼容旧选择计划及已冻结请求。
- 无公共 HTTP/SSE 或前端协议变化，无新增依赖；不修改旧 chartagent，不改动其他进程正在实施的任务回看或重复观察行为。
- 实施阶段更新 Agent、Provider、Memory 与总览相关文档；本 change 仅规划，不迁移实际会话数据。
