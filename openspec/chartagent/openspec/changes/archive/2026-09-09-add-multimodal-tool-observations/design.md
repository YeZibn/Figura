## Context

See `proposal.md` for motivation. The current `Tool.fn` contract accepts plain
callables, `dispatch()` serializes every result directly to JSON, and `Agent`
places that string in a native `tool` message. User-attached images already use
OpenAI-format `image_url` content, but generated images cannot cross the tool
boundary. The current endpoint is OpenAI-compatible rather than guaranteed to
support image parts directly in a `tool` message, and existing JSON-only tools
and MCP conversion must remain usable.

Project Python work is executed in the Conda environment named `agent`; all
non-interactive implementation and verification commands use
`conda run -n agent ...`.

## Goals / Non-Goals

**Goals:**

- Carry structured data, generated images, captions, and warnings through a
  typed internal tool-result contract.
- Preserve the current JSON observation behavior for legacy tools and callers.
- Present valid generated images to the same multimodal model on its next turn
  with unambiguous tool-call attribution.
- Produce deterministic, model-readable OCR and bar-detection overlays.
- Bound image formats, sizes, ownership, and retention without allowing tools
  to attach arbitrary local files.

**Non-Goals:**

- Adding chart routing, chart-type ICL retrieval, SAM, axis interpolation, or
  chart types beyond the current U0 scope.
- Requiring a tool sequence, a visual-verification action, a fixed confidence
  threshold, or ChartSpec output for every chart request.
- Proving that the model's visual judgment is correct; this change supplies the
  evidence and recovery path, not a correctness oracle.
- Replacing the existing user-image attachment syntax or moving away from the
  current OpenAI-compatible client.

## Decisions

### 1. Use a typed enriched result with in-memory generated images

Introduce internal value types conceptually shaped as:

```text
ToolResult
  data: JSON-serializable value
  images: list[GeneratedImage]
  warnings: list[str]

GeneratedImage
  content: bytes
  media_type: supported image MIME type
  caption: non-empty model-facing description
```

Tools return generated bytes rather than an arbitrary output path. The agent
validates the payload and converts it to a data URL through the multimodal
transport layer. This preserves local tool implementation freedom while making
the trust boundary explicit.

Alternative considered: allow tools to return local image paths. Rejected for
the initial capability because path ownership is difficult to prove and could
allow an unrelated local file to be attached to a remote model request.

### 2. Add enriched dispatch without breaking legacy `dispatch()`

Keep `dispatch(registry, name, arguments_json) -> str` as the compatibility
surface for existing tests, callers, and MCP wrappers. Add an enriched dispatch
path used by `Agent` that normalizes either a legacy value or `ToolResult` into:

```text
DispatchedObservation
  content: JSON string
  images: validated generated images
```

Legacy values produce the same JSON string and an empty image list. Enriched
results serialize `data`, warnings, and image metadata but never image bytes.
Tool exceptions and malformed structured data remain `{"error": ...}` results.
An invalid image is downgraded to a warning so valid data is not discarded.

Alternative considered: change `dispatch()` to return the new object. Rejected
because that would be a broad breaking change unrelated to callers that need
only JSON.

### 3. Preserve native tool ordering, then append one synthetic observation turn

For each assistant turn, the agent executes requested calls serially and first
appends one JSON `tool` message for every call. After all required tool messages
are present, it appends one multimodal message containing all valid images from
that batch. Its text explicitly states that it is generated tool evidence, not
a new user request, and groups every caption by tool name and `tool_call_id`.

The multimodal observation uses a `user` role because OpenAI-compatible Chat
Completions providers consistently accept image parts there, while image parts
inside `tool` messages are not portable. The next assistant turn can accept the
evidence, call another tool, or answer normally.

Alternative considered: place image parts directly in each `tool` message.
Rejected as the default because provider support is inconsistent; it can be
added later behind a transport adapter if verified.

### 4. Keep visual verification agent-driven and advisory

The default Agent guidance will explain that generated overlays are evidence
the model may inspect and that it may retry with changed arguments, select a
different tool, ignore an irrelevant result, or answer. No automatic retry is
triggered merely because an image exists, and no numeric threshold determines
acceptance.

This matches the project's free-planning direction. Deterministic warnings may
surface mechanical failures, but they inform the model rather than controlling
its plan.

### 5. Make overlays deterministic and cross-referenceable

`extract_text` will retain its current structured OCR entries and add a PNG
overlay at the source dimensions. Every returned region receives a stable
1-based identifier, visible bounding box, and concise confidence label; the
same identifier is added to the structured entry.

`measure_bars` will retain current bounds, heights, ratios, and baseline while
adding stable 1-based bar identifiers. Its PNG overlay marks each returned bar,
its identifier and top edge, plus the detected baseline. Empty successful
results still return an overlay of the source image with an explicit visual
indication that no regions were detected.

Pillow is already a project dependency and will be used for overlays. Labels
and strokes will use high-contrast deterministic colors and stay within image
bounds.

### 6. Bound payloads and retention

The initial transport accepts generated PNG, JPEG, and WebP payloads, with a
default maximum of 10 MiB per image and four generated images per tool call.
Malformed, empty, unsupported, oversized, or excess images become warnings and
are not attached. Valid siblings remain available.

Generated bytes are retained only through their encoded content in the owning
Agent's message history. `reset()` clears that history and any pending enriched
observations; an explicit close path performs the same release. Source image
files supplied by the user are never deleted or modified.

### 7. Verify provider transport separately from model reasoning quality

Offline tests use a recording client to assert exact role ordering, image data
URLs, captions, call IDs, backward compatibility, and bounded failures. A live
smoke in the Conda `agent` environment verifies that the configured multimodal
provider accepts the message sequence and can describe a deterministic overlay.
The smoke does not enforce a fixed tool plan and is not part of the deterministic
unit-test gate.

## Risks / Trade-offs

- **Synthetic user observations may be interpreted as new user intent** -> Use
  a fixed, explicit preamble identifying the content as tool-generated evidence
  and retain tool names and call IDs in the caption text.
- **Generated images increase request size and latency** -> Enforce image count
  and byte limits, emit one combined observation turn per tool batch, and keep
  overlays at source dimensions.
- **Provider rejects the multimodal turn after tool messages** -> Cover the
  exact sequence with a live compatibility smoke before considering the change
  complete; retain JSON-only behavior as a rollback path.
- **A plausible but wrong overlay can increase model confidence** -> Keep
  structured measurements visible beside the image and avoid describing visual
  observation as proof of correctness.
- **Enriched results complicate the simple tool protocol** -> Keep the legacy
  dispatch API and normalize plain return values automatically.
- **Base64 images remain in message history until reset** -> Apply strict
  payload limits and document reset/close as the memory-release boundary.

## Migration Plan

1. Add enriched result and transport types while keeping all existing tools on
   the legacy return path.
2. Switch `Agent` to enriched dispatch and prove that JSON-only history remains
   byte-for-byte compatible when no images are returned.
3. Add multimodal observation injection and provider compatibility coverage.
4. Opt `extract_text` and `measure_bars` into generated overlays.
5. Run the full suite and live smoke via `conda run -n agent ...`.

Rollback consists of disabling visual observation injection and returning the
two chart tools to their legacy data-only results; existing JSON dispatch and
user-image input remain intact throughout.
