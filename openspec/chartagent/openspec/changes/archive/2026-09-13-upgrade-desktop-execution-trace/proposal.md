## Why

Figura 当前可以通过 SSE 展示运行中的部分工具事件，但执行过程主要停留在前端内存和 Gateway 的短期运行缓存中。刷新页面、切换会话、下一次运行或 Gateway 重启后，用户无法回看工具调用、视觉观察和失败位置；最终回答也只能作为普通文本显示，难以阅读结构化分析结果。

本次升级将执行过程提升为可恢复的会话内容，并让最终回答以安全的 Markdown 形式呈现，使 Figura 更接近可检查、可回溯的 Agent 工作台。

## What Changes

- 新增持久化执行轨迹能力，保存每次运行的生命周期、模型轮次、工具调用、工具结果、视觉观察、错误和终态事件。
- 为 Gateway 增加历史运行与历史事件读取能力，并保留现有 SSE 实时事件流用于运行中的即时更新。
- 支持前端在刷新、切换会话和 SSE 断线后恢复已有执行过程，不再依赖单次页面生命周期。
- 将同一工具调用的调用、结果和视觉证据按 `call_id` 关联，形成可展开的步骤时间线。
- 在 React 客户端中增加 Codex 风格的运行级折叠面板和步骤级折叠面板，默认突出最终回答，过程内容可按需展开。
- 将 Agent 最终回答按安全 Markdown 渲染，保留原始回答内容并支持标题、列表、表格、代码块和强调文本。
- 对持久化事件、视觉产物和 Markdown 内容继续执行大小限制、敏感字段脱敏、资源授权和生命周期清理。
- 保留 mock 与 Gateway 两种客户端模式，不引入新的 Tauri 专属交互要求。

## Capabilities

### New Capabilities

- `execution-trace`: 持久化、恢复和展示 Agent 运行过程及最终 Markdown 结果。

### Modified Capabilities

- `desktop-client`: 扩展会话内容、执行时间线、断线恢复和 Markdown 回答的用户界面契约。
- `python-gateway`: 扩展运行事件的持久化、历史读取、SSE 补偿和视觉产物生命周期契约。

## Impact

- 影响 Python Gateway 的运行管理、SQLite 持久化、事件协议和运行/观察资源接口。
- 影响 React 客户端的协议类型、Gateway adapter、会话加载状态和消息/执行详情组件。
- 需要增加执行事件和视觉产物的存储限制、数据库迁移或兼容初始化逻辑。
- 需要增加前端 Markdown 渲染依赖或等价的安全渲染实现，以及 Gateway、React 和端到端恢复测试。
