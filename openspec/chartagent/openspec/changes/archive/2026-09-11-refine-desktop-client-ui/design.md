## Context

当前 React 入口集中在 `frontend/src/App.tsx`，已经按会话导航、对话区和附件区形成基本组件边界，并通过 `ChartAgentClient` 连接 mock 或 Gateway。样式集中在 `frontend/src/styles/global.css`，以浅灰背景和单一青绿色为主，信息层级、空状态、服务状态和响应式收缩仍较基础。现有 Python 包、环境变量、协议字段和数据目录都使用 `chartagent`，且不应因产品改名被破坏。

## Goals / Non-Goals

**Goals:**

- 建立 Figura 的统一用户可见身份，并在 mock、Gateway 和 Tauri 窗口中保持一致。
- 将现有工作区调整为清晰、克制、适合反复分析图表的桌面工作台。
- 提升会话、对话、工具执行、视觉观察、附件和运行状态的扫描效率。
- 保留现有 client boundary、Gateway 运行方式和附件预览生命周期。
- 让关键操作具备稳定布局、可见焦点和不依赖 hover 的可达性。

**Current Scope Boundary:**

- 后续实现与验证只覆盖 React/Vite 浏览器前端及其 Gateway 连接。
- 已完成的 Tauri 品牌配置保留，但暂不继续实现或验证 Tauri、Rust、Cargo 和 Xcode；Tauri 实机工作后续单独安排。

**Non-Goals:**

- 不在本变更中实现会话删除、重命名或回收站；会话操作区只保留后续扩展所需的稳定布局。
- 不重命名 `src/chartagent`、`python -m chartagent`、`CHARTAGENT_*`、协议头或本地数据目录。
- 不迁移 SQLite 数据，不改变 Gateway API 的数据结构和运行语义。
- 不引入新的组件库、状态管理库或远程字体/图片依赖。
- 不在当前变更中继续实现或验证 Tauri、Rust、Cargo 和 Xcode 相关内容。

## Decisions

### 1. 使用双层命名策略

产品层统一使用 `Figura`、`Figura Agent` 和 `Figura Gateway`；技术层继续使用 `chartagent` 作为 Python 模块、命令、环境变量前缀、协议兼容字段和数据目录标识。Tauri 的 `productName` 和窗口标题可以改为 Figura，但应用 `identifier` 暂时保持不变，以避免安装身份或后续升级路径发生变化。

选择这个方案是因为本次目标是改善产品体验，而不是进行一次破坏性包重命名。完整技术重命名需要另行设计别名、数据目录迁移和发布升级策略。

### 2. 在现有组件边界内重构展示层

保留 `SessionSidebar`、`ConversationPanel`、`Message` 和 `AttachmentPanel` 这些职责边界，整理 JSX 和事件属性，使每个区域的结构可读；继续通过 `ChartAgentClient` 获取数据，不让展示组件直接访问 fetch、SQLite 或 Tauri 命令。会话操作区域采用独立的可访问控件槽位，避免在会话选择按钮内嵌套另一个按钮，并为后续删除能力留下稳定位置。

选择这个方案是因为现有 mock/Gateway 行为已经由同一客户端接口驱动，拆换展示层可以降低回归面，也能修复当前会话项不适合承载多个操作的问题。

### 3. 建立有限的视觉令牌和信息优先级

在全局样式中集中定义背景、面板、边框、正文、次要文字、品牌强调、运行中、成功和错误颜色，以及统一的间距、控件高度和焦点样式。采用中性浅色画布配合 Figura 青绿色强调色，并使用琥珀色表示运行中、绿色表示完成、珊瑚红表示错误；不使用大面积渐变、装饰性光斑或过度圆角。

页面区域使用细分隔线和稳定网格轨道表达层级，重复附件和执行记录可以使用轻量卡片，但不把整页再套入多层卡片。助手答案和当前用户请求保持最高内容优先级，工具细节和视觉观察作为可展开或次级信息呈现。

选择令牌化样式而不是引入 UI 框架，是因为当前页面规模较小，现有 CSS 已覆盖布局和状态，新增依赖不会带来相应收益。

### 4. 采用浏览器前端的分级响应式布局

浏览器大窗口保持会话导航、主对话和附件检查三栏；中等宽度优先保证主对话与输入区，并将附件检查区收为次级区域；窄窗口改为会话横向导航、主对话、输入区和附件区的纵向布局。每个固定格式元素使用稳定的尺寸约束，避免状态文字或图标出现时布局跳动。

所有关键操作在窄窗口中仍有可见入口或键盘路径，附件和会话列表不依赖 hover 才能操作。这样既适配 Tauri 窗口缩放，也保留当前浏览器开发模式的可用性。

### 5. 保持状态和错误的语义，不仅改变颜色

运行状态、Agent 就绪状态、附件状态和错误状态继续使用现有协议值，并在 UI 中同时显示中文文字、图标或辅助文本。视觉调整不得把 Gateway 不可用误呈现为 mock，也不得把本地预览误呈现为模型已加载。错误提示仍通过现有 `toUserMessage` 归一化，产品名称替换不改变错误码。

## Risks / Trade-offs

- [产品名与 Python 包名不一致] → 在文档和代码注释中明确“Figura 是产品名，chartagent 是当前内部兼容标识”，并补充回归断言，避免后续误删兼容入口。
- [调整样式导致浏览器视口表现不一致] → 在 Vite 浏览器模式覆盖宽、中、窄三类视口，并保留稳定的响应式断点和尺寸约束。
- [会话操作区预留但暂时没有删除行为] → 本次只提供稳定布局和无歧义的现有操作，不添加不可用的删除按钮；删除能力在独立变更中接入完整 client/Gateway 链路。
- [重构 JSX 影响实时事件显示] → 保持事件到 `ConversationItem` 的转换和 `ChartAgentClient` 接口不变，优先做展示组件级回归和现有 smoke/build 检查。
- [修改 Gateway 展示名称影响严格测试或外部脚本] → 只修改面向人的 `service` 展示值，保留版本、字段名、路径、请求头和环境变量；同步更新项目内断言。

## Migration Plan

1. 先更新 React 展示层、样式令牌和 Figura 文案，再更新 Tauri 窗口展示名称、Gateway 人类可读服务名及文档。
2. 保留所有 `chartagent` 技术入口和现有数据目录，启动现有一键 Gateway 命令验证配置和会话数据未受影响。
3. 运行前端类型检查、构建、前端 smoke 和 Python Gateway 测试，并在 mock/Gateway 两种模式下检查浏览器中的品牌和状态展示；Tauri 实机检查延期到独立工作。
4. 如需回滚，只需恢复本变更涉及的前端、Tauri 展示配置、文档和展示名称；不需要数据回滚或数据库迁移。
