## Why

真实图表中的浅色坐标轴、旋转日期标签、图例和数据标注会干扰当前纯像素框检测。最近对双序列折线图的前端实跑显示，真实 Y 轴被漏检后生成了伪斜轴，横轴无法标定，无 marker 折线又被误识别出大量伪数据点；同时过长的工具结果会让前端丢失工具身份。需要让模型先提供语义布局先验，再由共享基础设施校验并供各图表传感器复用。

## What Changes

- 新增统一的图表布局上下文，描述主绘图区、坐标轴、刻度带、图例区和数据标注区，并支持正向、横向、旋转及可疑透视布局。
- 在图表观测链路中增加模型引导的布局预检；模型只提供归一化区域和方向提示，程序负责边界、轴关系、颜色轨迹和置信度校验。
- 将布局预检工具纳入统一的 `CHART_TOOLS` 注册路径，并沿用授权附件输入边界，避免 Gateway 额外维护一套重复注册逻辑。
- 让柱状图、折线图、散点图和饼图传感器消费经过校验的布局上下文，同时保留各自独立的 mark 测量逻辑。
- 改进折线图对日期/分类横轴和无 marker 连续折线的处理，避免把文字或连续线段峰值当作坐标轴和数据点。
- 约束低置信度布局、无法标定的横轴和冲突的模型/像素证据，保留可检查的像素证据并显式报告不确定性。
- 调整执行事件的截断策略，确保超长工具结果仍保留 `tool_name`、`call_id` 和执行状态，使前端能够正确归并工具步骤。
- 为布局预检补充统一的中文工具展示名，并保持模型描述与前端展示元数据解耦。

## Capabilities

### New Capabilities

- `chart-layout-context`: 为图表观测提供模型引导、程序校验且可复用的布局上下文。

### Modified Capabilities

- `chart-understanding`: 观测工具使用经过校验的布局上下文，支持日期/分类横轴和无 marker 折线，并在证据不足时保持部分结果。
- `execution-trace`: 超长工具结果截断时保留稳定的工具事件外层身份和状态。
- `desktop-client`: 在工具结果被截断或不完整时，仍按稳定调用标识正确展示工具步骤和状态。

## Impact

- Python 图表观测基础设施及 bar、line、scatter、pie 传感器。
- Agent 的多模态预检/工具调用编排，以及工具结果和视觉观察的传输边界。
- Gateway 执行事件序列化与持久化格式，以及 React 前端的运行过程归并。
- 不新增第三方依赖；继续使用 `agent` Conda 环境中的 RapidOCR 和现有模型客户端。
- 需要补充真实图片、旋转/横向图表、日期横轴、无 marker 折线和超长事件的回归测试。
