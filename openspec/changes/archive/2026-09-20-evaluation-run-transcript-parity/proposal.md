## Why

评测工作台目前把同一次运行拆成“轻量事件时间线”和“另一个详细记录视图”，与普通会话使用的完整运行时间线不一致。评测主时间线隐藏工具结果，详情投影又会因全局嵌套深度限制破坏 `bbox`、坐标、柱体和折线点等结构化数据，导致用户无法完整复盘一次评测。现在需要将评测记录改造成普通会话运行记录的只读等价视图。

## What Changes

- 统一评测与普通会话的运行历史 DTO，使评测能够展示同样的用户消息、模型消息、工具调用、工具结果、视觉观察、修复、审核、失败和恢复事件。
- 让评测 Gateway history 返回经过安全处理但结构保持完整的事件 payload；不再在主时间线把工具参数和结果替换为摘要占位符。
- 用语义化安全投影替代全局递归深度截断，保留图表几何、测量、坐标轴和证据字段，同时继续隐藏凭据、私有推理、绝对路径和图片二进制。
- 以 `gateway_run_events` 作为执行过程的主要来源，以 `records` 补充用户/模型可见对话，避免被截断的模型工具消息覆盖完整事件结果。
- 对超过事件传输上限的完整安全结果提供评测范围内的详情资源或等价分页读取方式，并明确区分持久化截断、读取投影截断和前端折叠。
- 抽取或复用普通会话的运行时间线组件和工具调用/结果关联逻辑，让评测区按 `call_id` 展开工具参数、结果与视觉证据。
- 保持评测只读、evaluation/case/run 归属校验、资源白名单和现有旧 bundle 的兼容；不改变普通会话的写入和运行行为。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `evaluation-workbench`: 修改评测运行历史、详细工具结果和前端只读运行记录的展示契约，使其与普通会话执行过程保持展示语义一致，并支持完整安全结果的读取。

## Impact

- Python：评测 reader、Gateway evaluation history API、事件/详情安全投影和大结果详情资源读取。
- React：评测 history 类型、Gateway client、运行时间线复用、工具结果展开、截断状态和视觉证据关联。
- 存储：兼容已有 `sessions.db`；必要时在评测 bundle 内登记受控的安全详情资源，不暴露 SQLite 或原始 provider payload。
- 测试与文档：增加当前 `bar_line_dashboard` 回归验证、深层几何结构、超限结果、缺失 records、敏感字段和普通会话回归覆盖。
