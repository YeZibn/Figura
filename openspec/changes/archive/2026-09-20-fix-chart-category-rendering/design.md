## Context

当前 `ChartSpec` 已经能够在 `Axis.categories` 中保存类别，但真实链路的
`assemble_spec` 输入只接受 `x_label` 和 numeric `x/y` points，导致从 panel 证据中
识别出的 `Jan`–`Jul` 没有进入 ChartSpec；随后折线生成路径只把数据点的数值 `x`
交给绘图库，类别标签也没有经过同一条生成路径。柱状图已有独立的类别刻度处理，因此问题集中在类别证据装配、折线图以及折线图的确定性保真审计。详见
`proposal.md` 和本 change 的两个 delta spec。

评测中出现的 `0`–`6`、`1`–`7` 不是数据点缺失，而是内部位置值被误当成了最终用户
可见的刻度文本。类别轴需要同时保留“用于绘图的位置”和“用于展示的标签”两层语义。

## Goals / Non-Goals

**Goals:**

- 让带有 `axes.x.categories` 的 line ChartSpec 生成可见、顺序正确的类别刻度。
- 让 `assemble_spec` 能把 line/scatter 的有序横轴类别从工具输入传递到 ChartSpec。
- 让单系列和多系列折线共享同一组类别位置，并保持原始数据点的数值语义。
- 在生成前/后尽早发现类别数量、顺序、文本和位置映射不一致，并阻止错误候选发布。
- 保持现有 bar 类别渲染和无类别的 numeric line/scatter 输入兼容。
- 用离线回归测试覆盖本次真实评测暴露的缺陷，不依赖 provider、OCR 或 VLM。

**Non-Goals:**

- 不改变 VLM 审核协议、审核 prompt、OCR/SAM 链路或测量工具。
- 不把所有折线图强制转换成类别轴；没有类别域的折线仍是数值横轴。
- 不在本 change 中解决 composite figure 覆盖率告警、provider 失败或评测报告展示问题。
- 不引入新的绘图库或外部依赖。

## Decisions

### 1. 用统一的类别位置适配层连接 ChartSpec 与渲染器

生成路径在绘制折线前先准备一个有界的离散横轴映射：

- `axes.x.categories` 是按显示顺序排列的标签列表；
- 数据集中的有序、去重后的数值 `x` 位置是绘图坐标；
- 第 `i` 个类别标签绑定第 `i` 个有效 x 位置；位置值可以是 `0..n-1`、`1..n`
  或其他合法数值，不能直接作为用户可见标签；
- 多系列必须共享同一套类别位置；单个系列缺少某个点时不创建虚假的零值；
- 类别数与可用位置无法一一对应时返回结构化问题，而不是猜测或静默重排。

这样既兼容模型输出的 0-based/1-based 月份位置，也不会把“采用哪一种内部索引”
暴露成 ChartSpec 的新字段。类别域未提供时，不启用适配层，保留绘图库的数值刻度。

备选方案是把 line 的 `DataPoint` 改成 `category + value`，但这会破坏当前 line/scatter
的坐标模型，并使连续数值轴难以表达，因此不采用。

### 2. 在 assemble_spec 入口显式传递类别证据

单图和 figure child 输入新增可选的 `x_categories` 数组。装配器对它执行有界的输入
校验，并在 cartesian ChartSpec 中写入 `Axis.categories`；figure child 逐项传递自己的
类别域，不能从其他 child 或 panel 推断/合并。没有该字段时保持 `categories=None`，
避免为纯数值轴虚构类别。

备选方案是让 renderer 根据 `x_label` 或源图片再次 OCR 推断类别，但这会把装配责任
推迟到生成阶段、引入不可确定的二次识别，也会破坏 evidence 到 ChartSpec 的可追溯性，
因此不采用。

### 3. 通过显式 tick 设置呈现类别，而不是依赖绘图库自动推断

折线绘制完成后，生成器显式设置类别位置和类别文本，并重新应用字体与必要的布局
处理。轴标题仍由 `axes.x.label` 独立设置；不能把 `Month` 之类的轴标题当成唯一的
类别信息。标签需要旋转或增加边距时，只调整布局，不改变标签顺序和绑定位置。

备选方案是仅修改 prompt，让模型把 x 写成字符串或依赖 VLM 在审核中纠正。该方案
不能保证确定性生成，且当前评测已经证明“ChartSpec 有类别但最终图片丢标签”是代码
边界问题，因此不采用。

### 4. 将类别保真加入现有确定性审计

折线审计沿用已有 artist/value 检查，并增加三组事实检查：

1. 最终 tick 文本与 ChartSpec 类别完全一致；
2. tick 数量和顺序与类别域一致；
3. 每个系列的 x 数据能对应到相同的类别位置。

失败位置统一定位到横轴类别或折线数据映射，并进入现有生成门禁；VLM 仍然负责补充
视觉语义判断，但不能替代这组代码可确定验证。无类别的数值折线不执行类别文本检查。

### 5. 先用离线生成回归覆盖，再用真实评测复验

测试分四层：assemble_spec 的类别传递、ChartSpec 类别边界/序列化、折线生成图片的
tick 文本、审计对错误 tick 的拒绝。确认离线行为后，重新运行现有 bar+line 真实评测，
检查 Monthly Orders 的类别标签和候选审计结果。这样可以把装配、renderer 缺陷与
provider/VLM 波动分开。

## Risks / Trade-offs

- [类别位置不完整或多系列 x 集合不一致] → 在生成前返回定位到 `axes.x.categories`
  或数据点的结构化错误，不尝试补点或补零。
- [类别很多或文本较长导致拥挤] → 复用已有画布边界、字体和密度审计；允许受控旋转/间距，
  但仍要求每个标签可识别且顺序不变。
- [已有调用方误把类别列表当作装饰信息] → 明确它现在是生成语义的一部分；没有类别
  列表的旧数值折线路径保持不变，只有声明类别但无法映射的输入会被拒绝。
- [VLM 与确定性审计对类别的判断不一致] → 以 ChartSpec 和代码审计作为生成门禁，
  将 VLM 作为额外的源图/视觉一致性审核，不允许 VLM 通过缺少刻度的候选。

## Migration Plan

1. 先实现类别位置适配、折线 tick 设置、ChartSpec 边界校验和确定性审计，并补齐离线测试。
2. 运行完整 Python 测试、OpenSpec 校验和现有真实 bar+line 评测，确认 bar 未回归且
   Monthly Orders 显示 Jan–Jul。
3. 若真实评测仍失败，优先读取确定性审计输出区分 ChartSpec 输入问题、渲染问题和 VLM
   语义问题；不通过修改 prompt 掩盖渲染失败。
4. 回滚时只需撤销该 change 的渲染/校验代码和回归测试；没有持久化数据迁移或外部
   服务迁移。

## Open Questions

无。类别标签是否应进入最终图片、如何与 x 位置绑定以及失败时是否允许发布，均已由
本 change 的 spec 和上述设计确定。
